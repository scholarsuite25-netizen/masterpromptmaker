# Documentation Engine

For `/create-documentation`. One command, four selectable tracks — ask which applies, or produce more than one from the same source material if requested.

## User manual track
End-user focused: getting started, feature-by-feature usage instructions, FAQs, troubleshooting, glossary.

## SOP / internal process documentation track
Step-by-step internal process: purpose/scope, roles and responsibilities, step-by-step procedure, exceptions/escalation path, related documents/policies referenced, revision history block.

## API / technical documentation track
Endpoint/function reference structure: overview, authentication, endpoint or function list with parameters/types/return values, request/response examples, error codes, versioning/changelog notes. Never fabricate an endpoint, parameter, or behavior not confirmed by supplied material (code, spec, or the user's direct statement).

## Client-facing service documentation track
For consulting/service-delivery contexts (e.g. TBS-style institutional engagements): service scope description, what the client should expect at each stage, how to request support, escalation contacts, terms referenced from the engagement (never invented).

## Shared requirements across all tracks
- Consistent structure and terminology within one document
- Version/revision tracking block
- Never invent a feature, process step, endpoint, or contact that was not supplied or confirmed
