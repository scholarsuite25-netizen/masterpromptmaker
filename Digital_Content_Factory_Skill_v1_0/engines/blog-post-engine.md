# Blog Post Engine

For `/create-blog-post`. Independent factory — does not depend on or feed the Social Media Calendar Engine, though either may be used to repurpose the other's output if the user asks for that separately.

## Post types (select one per post, or the user may request a mixed set from the same source material)
- How-to / tutorial-style post
- Thought-leadership / opinion post
- Listicle
- Case study
- News / announcement post

Ask which type if not stated or obvious from supplied material; each type has a different structural default (see below).

## Standard SEO section (default on, not optional per project instruction)
- Target keyword/topic confirmed with the user before drafting
- Meta title and meta description drafted to length convention (do not fabricate search-volume or ranking claims)
- Header hierarchy (H1/H2/H3) built around the topic structure, not stuffed with the keyword mechanically
- Alt-text prompts flagged at each image placeholder, describing what the image should show and a suggested alt-text line
- Internal/external linking guidance: where a link would help, what anchor text to use — never a constructed or guessed URL; flag `[LINK VERIFICATION REQUIRED]` if a link's target can't be confirmed
- A short suggested slug/URL

## Type-specific structure
- **How-to**: intro (problem framed), prerequisites, numbered steps, common pitfalls, summary/recap, CTA
- **Thought-leadership**: hook, position stated early, supporting argument developed, counterpoint acknowledged, conclusion, CTA
- **Listicle**: intro framing the list's purpose, numbered/titled items each with a short explanation, closing wrap-up, CTA
- **Case study**: context/challenge, approach, result (never fabricated figures — use only what's supplied), takeaway, CTA
- **News/announcement**: lead with the news itself, key details, why it matters, next steps/CTA

## Series / pillar content (optional extension)
When the user wants a linked series:
1. Define the pillar post (the broad, comprehensive anchor piece) and the supporting posts (narrower posts on sub-topics).
2. Each supporting post links back to the pillar post; the pillar post links out to each supporting post once published.
3. Maintain a single series-level content map (pillar + supporting posts, working titles, status) so the set stays coherent rather than drifting into unrelated topics.
4. Single-standalone-post remains the default mode — series mode is opt-in, not assumed.

## Never
- Fabricate statistics, testimonials, case-study results, or search-performance claims.
- Construct or guess a URL for internal/external linking.
- Force SEO keyword density that damages readability — flag the tension rather than degrading the post silently.

Apply the Editorial Naturalness Engine's prose standard by default.
